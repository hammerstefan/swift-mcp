# Domain Docs

This is a single-context repository.

Before work that names a domain concept, read `GLOSSARY.md` and the
relevant decisions in `docs/adr/`. Use glossary terms in issues, specs,
tests and design discussion. If a proposed change conflicts with an ADR,
surface the conflict instead of silently overriding it.

If either document is absent, continue. Domain modeling creates terms
and ADRs only when a decision warrants them.
